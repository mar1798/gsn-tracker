## 1. Суть продукта

Пользователь тренируется в зале с часами Garmin в режиме **Strength (Силовая)**. Часы записывают тренировку: подходы (время начала, длительность, повторы, иногда вес и категорию упражнения), отдых, посекундный пульс и калории.

GSC Tracker:
1. **Импортирует** тренировку Garmin (FIT-файл).
2. **Разбирает** её на подходы и считает пульс по каждому подходу (средний и максимальный).
3. Позволяет пользователю **дополнить** каждый подход: конкретное упражнение, вес, исправленные повторы, RPE, заметка.
4. По упражнениям определяет **группы мышц** и строит **аналитику прогресса**: объём по группам мышц, рост весов, оценку 1ПМ, личные рекорды, пульсовую нагрузку.

Ключевой принцип: **данные Garmin — неизменяемый слой, разметка пользователя — отдельный слой поверх него.** Повторный импорт или синхронизация никогда не затирают то, что ввёл пользователь.

Язык интерфейса: русский. Код, имена переменных, таблиц и коммитов: английский.

## 3. Интеграция с Garmin — архитектура источников

Все источники данных Garmin реализуют один интерфейс, чтобы их можно было менять без переписывания остального кода:

```ts
interface GarminSource {
  id: 'manual_fit' | 'garmin_activity_api' | 'terra';
  // получить FIT (или уже нормализованную тренировку) по внешнему событию / загрузке
}
```

Порядок реализации:
1. **`manual_fit`** (MVP): пользователь экспортирует «Export Original» с connect.garmin.com и загружает FIT в приложение через document picker или share sheet. Приложение отправляет файл на бэкенд, бэкенд парсит.
2. **`garmin_activity_api`** (после одобрения в Garmin Connect Developer Program): OAuth-подключение аккаунта, вебхук о новой активности, загрузка FIT, тот же пайплайн парсинга.
3. **`terra`** (альтернатива, если Garmin не одобрит доступ): вебхук Terra, загрузка данных или FIT, тот же пайплайн.

Правила:
- **Не используй неофициальные API Garmin** (логин и пароль, скрейпинг connect.garmin.com).
- **Не выдумывай эндпоинты и форматы** Garmin или Terra. Пока нет документации и ключей, делай адаптеры заглушками за интерфейсом, с TODO и ссылкой на то, что нужно уточнить. Уточняющие вопросы задавай мне.
- Дедупликация: по `garmin_activity_id`, если он есть, иначе по SHA-256 файла. Повторная загрузка того же файла не создаёт дубль.

## 4. Разбор FIT (`packages/fit-parser`)

Вход: `Buffer` / `Uint8Array` FIT-файла. Выход: нормализованный объект `ParsedWorkout`.

Что извлекать:
- **session**: sport / sub_sport (проверка, что это силовая), start_time, total_elapsed_time, total_timer_time, total_calories, avg_heart_rate, max_heart_rate.
- **set**-сообщения: start_time, duration, set_type (active / rest), repetitions, weight, category, category_subtype, message_index.
- **record**-сообщения: timestamp + heart_rate (посекундный пульс).
- **device_info / file_id**: модель часов, серийный номер (для отображения), garmin activity id, если есть.
- **session.activeTime** (чистое время под нагрузкой), **timeInZone** (время в пульсовых зонах и их границы), **userProfile.weight / height** (вес тела для упражнений с собственным весом), **deviceSettings.timeOffset** (сдвиг часового пояса).

### Реальные наблюдения (фикстура `fixtures/fit/2026-10-17_strength_epix2pro.fit`, Epix Pro Gen 2)
Проверено на реальном файле через `@garmin/fitsdk` с опциями `{ convertDateTimesToDates: true, expandComponents: true, mergeHeartRates: true }`. Ожидаемые значения лежат в `2026-10-17_strength_epix2pro.expected.json`, тест сверяет с ними.
- Имена полей SDK в camelCase: `messages.setMesgs`, `recordMesgs`, `sessionMesgs`; `setType` — `'active' | 'rest'`; спорт — `sport: 'training'`, `subSport: 'strengthTraining'`.
- 42 `set`-сообщения = 21 active + 21 rest, они строго чередуются. Сумма `repetitions` по active = 326 (совпадает с Garmin Connect). Сообщений `lap` нет, хотя `session.numLaps = 42`.
- **`weight` всегда 0.** Часы вес не знают, вес вводит пользователь. `0` → `null`.
- **`repetitions` недостоверны**: это шаблонное значение часов (50, 10, 10, 10…, иногда 6), а не реальный подсчёт. Показывай как предзаполнение с явным признаком «от часов» и делай удобное исправление.
- **`category` — массив из 3 догадок**, например `['row','unknown','curl']`; `categorySubtype` — массив той же длины, обычно `null`. Отфильтруй `'unknown'`, сохрани весь список как `garmin_hints: string[]` (порядок = приоритет). Догадки часто ошибочны (11 из 21 подхода — «curl / benchPress»), поэтому **никогда не применяй их автоматически**, только как подсказку.
- **Ложные подходы**: у подходов 12 и 13 `duration` < 2 с (двойное нажатие кнопки). Помечай подходы с `duration < 5 с` как `suspicious: 'too_short'`. В UI предлагай «удалить» или «объединить с соседним».
- Пульс пишется примерно раз в 2 с (smart recording, разрывы до 13 с), а не посекундно. Агрегаты считай по фактическим точкам, без предположения о частоте.
- Все `timestamp` в UTC, локальный сдвиг лежит в `deviceSettings.timeOffset` (21600 с = UTC+6). Храни UTC, а отображай в часовом поясе пользователя.

Вычисления:
- Только `active`-подходы считаются подходами. `rest` используется для расчёта отдыха после подхода.
- Для каждого подхода: avg_hr, max_hr, min_hr по `record` в окне `[start_time, start_time + duration]`, а также `rest_after_sec`.
- **Пиковый пульс подхода (`hr_peak`)** = максимум в окне `[start_time, end + 30 с]`. Пульс достигает пика уже после окончания подхода: в фикстуре у подхода 10 максимум внутри окна — 149, а с учётом 30 с после — 169. `hr_peak` — основная пульсовая метрика подхода в UI и аналитике. Окно 30 с вынеси в константу.
- Калории по подходам: Garmin даёт калории только на сессию. Распредели их по подходам пропорционально `duration × avg_hr` (явно пометь как оценку: `calories_estimated: true`).
- `category` / `category_subtype` маппятся в человекочитаемое название через профиль FIT SDK (exercise category types). Это **подсказка** для разметки, а не истина.
- Неизвестные или пустые значения (weight 0, повторы отсутствуют, категория UNKNOWN) → `null`, без падений.

Требования:
- **Перед реализацией** напиши скрипт `pnpm fit:dump <file>`, который печатает все типы сообщений и поля из реального FIT-файла из `fixtures/fit/`. Сверь реальные имена полей и значения enum в выводе `@garmin/fitsdk` (camelCase, строки или числа) и только потом пиши маппинг. Не полагайся на память.
- Покрой парсер unit-тестами на реальных фикстурах и на синтетических краевых случаях (нет пульса, нет set-сообщений, только отдых, тренировка не силовая → понятная ошибка).

## 6. Аналитика (`packages/shared/analytics`)

Чистые функции с unit-тестами:
- **Объём подхода** = reps × weight. Для упражнений с весом тела используй вес тела пользователя × коэффициент (настраивается) или считай отдельно (повторы).
- **Объём по группе мышц** = Σ(объём × coefficient). Плюс **количество рабочих подходов** на группу мышц (primary = 1, secondary = coefficient). Разминочные и исключённые подходы не учитываются.
- **e1RM** по Эпли: `w × (1 + reps/30)`, только для reps ≤ 12.
- **Личные рекорды**: максимальный вес, максимальный e1RM, максимальный объём за подход и за тренировку по упражнению.
- **Пульс**: средний пульс рабочих подходов, **пиковый пульс подхода `hr_peak`** (с окном +30 с после подхода, см. раздел 4), время в пульсовых зонах (берётся из `timeInZone` Garmin, а не пересчитывается), восстановление пульса за время отдыха (падение bpm за 60 с после пика, если хватает данных).
- **Плотность тренировки** = `session.activeTime / totalTimerTime` (в фикстуре 18:55 из 1:11:36 ≈ 26%). Показывай в итогах тренировки и в трендах.
- **Упражнения с собственным весом**: вес по умолчанию берётся из `userProfile.weight` в FIT (в фикстуре 78 кг), пока пользователь не задал свой в настройках.
- **Повторы и объём**: в объём и e1RM идут только повторы и вес, подтверждённые или введённые пользователем. Подходы, где нет веса или упражнения, не участвуют в весовой аналитике, но учитываются в подсчёте подходов и в пульсовых метриках.
- **Агрегации**: по неделе, месяцу и произвольному периоду; сравнение с предыдущим периодом.

## 7. Экраны мобильного приложения

Табы:
1. **Тренировки**: лента импортированных тренировок (дата, длительность, ккал, средний пульс, статус разметки «размечено 8/12 подходов»). Кнопка «Импорт FIT».
2. **Прогресс**: тепловая карта мышц за период, объём по группам мышц (график по неделям), список упражнений → экран прогресса упражнения (вес / e1RM / объём во времени, рекорды).
3. **Упражнения**: справочник с поиском и фильтром по группе мышц, создание своего упражнения.
4. **Профиль**: подключение Garmin, настройки (кг/фунты, максимальный пульс, зоны, вес тела), экспорт данных CSV, выход.

Ключевой экран — **«Разметка тренировки»** (детали тренировки):
- Сверху график пульса всей тренировки с подсвеченными подходами (тап по зоне → переход к подходу).
- Ниже список подходов: №, время, длительность, отдых после, повторы Garmin, пульс (средний и максимальный), выбранное упражнение.
- Тап по подходу открывает bottom sheet: выбор упражнения (поиск, недавние, подсказка Garmin первой), вес, повторы (предзаполнены значением Garmin), RPE, разминка / отказ / исключить, заметка.
- **Быстрая разметка**: «Применить упражнение и вес к следующим N подходам» и «Отметить подходы 1–4 как Жим лёжа». Типичная тренировка — 3–5 упражнений по 3–5 подходов, разметка должна занимать меньше минуты.
- Добавление ручного подхода, если часы пропустили.
- Итог тренировки: группы мышц (мини-карта тела), общий объём, новые рекорды.

UX-требования: тёмная тема по умолчанию (зал), крупные зоны нажатия, haptics на подтверждение, пустые состояния с подсказками, скелетоны при загрузке, понятные сообщения об ошибках («Это не силовая тренировка», «Файл уже импортирован»).

Внутри формы нужны обычные RN-компоненты (поля ввода, поиск по справочнику), которые в SwiftUI-sheet пришлось бы оборачивать в `RNHostView`. Маршрут-sheet тестируется через router.
  - **Офлайн-очередь правок**: каждая правка (`WorkoutEdit` из `shared`: PUT/bulk аннотации, создание/изменение/удаление ручного подхода) сначала пишется в SQLite (`pending_edits`) и сразу видна на экране: `applyWorkoutEdits` накладывает очередь на последнее состояние сервера. Затем правки отправляются строго по порядку (`src/lib/outbox.ts`). Сеть, 5xx и 401 оставляют правку в очереди и повторяют её через 15 с, при возврате приложения на передний план и после успешной загрузки тренировки. 4xx — правка удаляется, на экране показывается причина. Ответ сервера вливается в кэш до перезагрузки тренировки, поэтому значения не «прыгают» назад. При выходе из аккаунта очередь удаляется вместе с кэшем.

Тот же `id` в чужой тренировке — 409 `id_conflict`. Остальные правки идемпотентны сами по себе, удаление уже удалённого подхода (404) считается успехом.
  - Детали тренировки, пульс и справочник кэшируются в SQLite (`cached_workout_details`, `cached_exercises`), разметка работает без сети. Миграция SQLite v2.
  - **Повторы «от часов»**: в sheet одного подхода повторы предзаполнены значением часов с пометкой «от часов — проверьте». Сохранение sheet подтверждает показанное значение (`reps_source = user`). В массовой разметке поля пустые, и в patch идут только изменённые поля, поэтому повторы часов остаются неподтверждёнными.
  - **Ложные подходы** (короче 5 с) не удаляются и не сливаются: слой Garmin неизменяемый. В sheet объясняется, что подход нужно исключить, а повторы при необходимости добавить к соседнему. Настоящее слияние с пересчётом пульса — изменение схемы, отложено до запроса.
  - **Массовая разметка**: «Выбрать» в шапке или долгое нажатие на подход включает режим выбора, долгое нажатие на другой подход добавляет диапазон («1–4»). «Применить к следующим N» в sheet одного подхода переносит упражнение (и вес, если указан) на следующие рабочие подходы, пропуская короткие и исключённые.
  - **Быстрый выбор упражнения** (`exerciseShortcuts`): сначала подсказки часов, затем упражнения предыдущих подходов этой тренировки (ближайшие первыми), затем недавние (локальная таблица `recent_exercises`). Подсказка часов никогда не выбирается автоматически. Поиск (`searchExercises`) — на клиенте по всему справочнику: все слова в любом порядке, `ё` = `е`. При выборе упражнения пустой вес предзаполняется последним весом этого упражнения в тренировке.
  - График пульса: SVG-линия с полупрозрачной заливкой, подходы — полосы (короткие расширены до 3 pt). Тап выбирает ближайший подход, список прокручивается к нему и подсвечивает его.
  - Итог тренировки (мини-карта мышц, объём, рекорды) остаётся в фазе 6, как в описании фаз.
- **2026-10-19, фаза 5 (справочник упражнений).**
  - Новых зависимостей нет.
  - **API**: `POST /exercises` (201), `PATCH /exercises/:id` (только переданные поля, `muscles` заменяется целиком), `DELETE /exercises/:id` (204). Встроенные упражнения — 403 `builtin_exercise`, чужие — 404. Мышцы проверяет `customExerciseMusclesSchema`: без повторов, хотя бы одна основная, у основной коэффициент 1, у вспомогательной меньше 1.
  - **Удаление мягкое**: колонка `exercises.archived_at` (миграция `0001`). Подходы, размеченные удалённым упражнением, сохраняют его (название, мышцы для аналитики фазы 6). `GET /exercises` отдаёт и удалённые с `isArchived: true`, чтобы клиент показывал их название в тренировках. Справочник и выбор упражнения их скрывают, в подсказки Garmin они не попадают. Повторное удаление — 204.
  - **Уникальность названия**: среди своих и встроенных активных упражнений, без учёта регистра, `ё` = `е`. Дубль — 409 `duplicate_name` с `exerciseId`. Название удалённого упражнения снова свободно.
  - **Свои упражнения меняются только онлайн**, не через офлайн-очередь: проверка названия требует сервера. Ответ сервера сразу записывается в кэш справочника (TanStack Query и SQLite), без перезагрузки.
  - **Роли мышц в форме**: «Основная» (коэффициент 1) и «Вспом.» (0,5 для новой мышцы). При редактировании вспомогательная мышца сохраняет свой коэффициент. Произвольный коэффициент в UI не вводится, API его принимает.
  - **Справочник** (вкладка «Упражнения»): клиентский `filterExercises` в `shared` (поиск, «Мои», группа мышц; сначала упражнения, где мышца основная). Карточка упражнения: доли мышц полосами, оборудование, тип, вес тела, есть ли аналог у часов. Форма — модальный экран `/exercise-form?id=` или `?name=`.
  - Если поиск в разметке подхода ничего не нашёл, есть кнопка «Создать «…»»: она открывает форму с этим названием. Созданное упражнение сразу находится в том же поиске, но автоматически не выбирается.
